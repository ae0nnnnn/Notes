## Relational Databases 

These are databases that are linked by relationship

There 3 types of relationships
- One to One (1:1)
- One to Many (1:M)
- Many to Many (M:M)

This requires a common field inorder for the relationship work.

We also need each record in the within a table to be uniquely identifiable.

As a result there must be at least one field in each record that is guaranteed to be unique -- this field is known as the **primary key**: 

If a table has a relational link to another table we also have what are known as **foreign keys**.

The primary Key of Table B would be the foreign key of Table A

## Using indexing and secondary keys

A database is only useful if we can quickly query it to quickly retrieve information.

The database automatically maintains an **index** of primary keys so that a specific primary key can be located quickly and easily.

The index provides the position of each record according to its primary key - this makes retrieval of records referenced by the index much quicker, as items  do not need to searched sequentially.

You can also specify one or more secondary key fields to be indexed. You would do this for fields that are often used as search criteria.

Say you need to search for a student in a database - The likelihood of you remembering their ID number is low however there is a good chance you know their last name so you can set a secondary index based on the surname field.

The surname field then becomes a secondary key in the student table

## Normalization of Data 

### 1NF

To get to first normal form (1NF) a table should follow the five rules 
1. All field names must be unique
2. Values in fields should be from the same domain.
3. Values in fields should be atomic 
4. No two records can be identical
5. Each table needs a primary key.
   
### 2NF
To get to second normal form (2NF), a table should follow two rules 

1. The data is already in 1NF
2. Any **Partial Dependencies** are removed.
   
When looking to split a table up ask yourself the questions *"What can I infer from this field?"*

If a field or group of fields can be inferred from a field that isn't the primary key this means that they are prime pickings to be split into a new table.



### 3NF
1. The Data is already in 2NF
2. Any **Transitive dependencies** have been removed 


For this you can use the phrase "All fields are dependent on the key the whole key and nothing but the key"

## Referential Integrity 

Databases can hold vast amounts of information and often need to support need to support multiple simultaneous users.

**Large databases** could have millions of records and thousands of active users.

Users can be given different access rights to a database:

- Some will only be able to query the database and run reports.
- Others will be able to add and modify records
- A select few may be allowed to delete records.


All these different database queries result in multiple **transactions** taking place at mostly the same time.

It is in important that this process never makes database become **inconsistent** or **corrupted**. 

If transactions cause the database to become inconsistent, we can no longer guarantee its accuracy.


For what every type of transaction is taking place the **DBMS (Data Management System)** ensures that the data stored in the database remains consistent 

The Process of maintaining the consistency of the database is also known as **data integrity**.

Being able to guarantee the integrity of data being held in a database is of vital importance.


A key technique for ensuring data integrity in a relational database is known as **referential integrity**.
